## Root Cause

**`apiFetch()` returns `json.data`, but `adminLogin()` treats that return value as if it were the full response.**

In `Response.php`, every successful response is wrapped:
```json
{ "success": true, "data": { "token": "...", "expires_at": "...", "admin": {...} } }
```

`apiFetch()` correctly unwraps this and returns `json.data`. So inside `adminLogin()`, `data` is already `{ token, expires_at, admin }` — that part is fine.

**The actual bug is in `apiFetch()`'s token resolution logic:**

```js
const token = (typeof App.session !== 'undefined')
  ? (App.session.getSessionToken() || App.session.getAdminToken())
  : (localStorage.getItem('rcy_gallery__admin_token') || '');
```

`App.session` is **always defined** (it's declared in the same `api.js` file, below `App.api`). So the ternary always takes the left branch. `App.session.getSessionToken()` reads `rcy_gallery__<eventSlug>__sessionToken` — which on the login page resolves the slug via `window.MOCK_DB.event.slug` (since there's no `/event/` in the URL). **The real problem:** after `adminLogin()` writes the token to localStorage and the page redirects to `super/dashboard.html`, `requireSuperAdminOrRedirect()` runs synchronously and calls:

```js

```

The backend returns `expires_at` as `2026-08-29 14:59:11` (Asia/Manila time). After `.replace(' ', 'T')` it becomes `2026-08-29T14:59:11` — **no timezone suffix**. `new Date()` parses this as **local time** in the browser. ### Bug 1 — Token was being immediately cleared on redirect (the primary cause)

The backend returns `expires_at` as `2026-08-29 14:59:11` — a Manila time (UTC+8) string with no timezone suffix.

Both `requireAdminOrRedirect()` and `requireSuperAdminOrRedirect()` parsed it with:

The ECMAScript spec treats a date-time string without a timezone offset as **local time**.
